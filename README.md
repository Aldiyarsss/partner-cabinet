# Кабинет партнёров

Прототип личного кабинета банка для подключения партнёров и работы с документами:
застройщиков (ЖК) и автосалонов (дилерские центры).

Весь кабинет это один файл `index.html`. Сервер, база данных и сборка не нужны.

## Как разместить на GitHub Pages

1. Создайте репозиторий на GitHub, например `partner-cabinet`.
2. Загрузите в корень репозитория все файлы из этой папки:
   `index.html`, `README.md`, `.nojekyll`, `THIRD_PARTY_NOTICES.txt`
   (на странице репозитория: **Add file → Upload files** → **Commit changes**).
3. Откройте **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**,
   ветку `main` и папку `/ (root)`, нажмите **Save**.
5. Через 1–2 минуты кабинет будет доступен по адресу
   `https://<ваш-логин>.github.io/partner-cabinet/`.

Для приватного репозитория GitHub Pages доступен только на платных тарифах GitHub.
Файл `.nojekyll` скрыт в проводнике Mac; если его не видно, создайте в репозитории пустой файл с этим именем.

## Как устроен процесс

0. Внешние согласования проводятся вне системы.
1. **Карточка партнёра.** Главный специалист филиала ищет партнёра по БИН/ИИН. Если не нашёл, создаёт карточку.
2. **Подписание документов.** Договор о сотрудничестве загружается в Word, система делает PDF.
   Маршрут: начальник управления филиала → директор партнёра (ЭЦП) → директор филиала (ЭЦП).
   После подписания формируется PDF со штампами подписей.
3. **ЖК / ДЦ.** Данные объекта, документы (акт ввода, техпаспорт, справка форма-2 или разрешительный документ), фото
   и заключения СБ, юристов и комплаенса. Заключения общие для партнёра и запрашиваются снова только после истечения срока.
   Согласование: начальник управления филиала → сотрудник ГО (общая очередь) подключает или возвращает на доработку.
   К подключённому ЖК можно добавить корпус, к ДЦ ещё один адрес.
4. **Договор о сотрудничестве** — итоговая карточка подписанного договора.
5. **ДС** создаются в любой момент: изменения, продление срока, иное. ДС о продлении переподключает партнёра после истечения договора.
6. **АВР** формируются вручную из карточки партнёра: сотрудник ГО → директор партнёра (ЭЦП) → директор департамента (ЭЦП).

## Где хранятся данные и документы

Партнёры, договоры, АВР, журнал и загруженные файлы (Word, PDF, сканы, фото) сохраняются
в хранилище браузера (IndexedDB) и не пропадают после перезагрузки страницы.

Важно:
- данные живут **в браузере конкретного компьютера**, коллега на другом компьютере их не увидит;
- очистка данных сайта или режим инкогнито удаляют их;
- в меню пользователя (справа вверху) есть **«Скачать резервную копию»**, **«Восстановить из копии»**
  и **«Очистить все данные»**.

## Вход

- Администратор: `aldiyars@freedombank.kz`. При первом входе введите email, нажмите «Войти» и задайте пароль
  (минимум 8 символов, буквы и цифры).
- Администратор заводит сотрудников в разделе «Пользователи»: ФИО, роль, филиал, email. Сотрудник задаёт пароль при первом входе.
- Директор партнёра входит по email из карточки партнёра после выдачи доступа.
- Вход работает в пределах браузера, где созданы учётные записи: общей базы нет.

Кабинет стартует пустым, все данные создаются вручную.

## Ограничения прототипа

- **Подпись ЭЦП имитируется.** В рабочей версии подписание идёт через NCALayer, а проверка подписи
  (OCSP, TSP НУЦ РК) и хранение CMS выполняются на сервере банка.
- **Вход по паролю не является защитой**: проверка выполняется в браузере, код открыт. Не размещайте реальные данные.
- **Письма** не отправляются, они видны в меню пользователя → «Уведомления».
- **Word → PDF** в браузере упрощённый: текст и таблицы сохраняются, сложная вёрстка может отличаться;
  поддерживается `.docx`, старый `.doc` не читается.
- Для общей работы нескольких сотрудников нужен сервер: база данных, файловое хранилище,
  авторизация, NCALayer и почта.
